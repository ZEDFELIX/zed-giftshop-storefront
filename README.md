# ZED Gift Shop — Storefront

A complete static storefront for **ZED Gift Shop**, Nairobi. The layout and
shopping experience are modelled on [riogiftshop.com](https://riogiftshop.com/);
ZED keeps its own logo, name, palette, copy and product data.

Live: <https://zedfelix.github.io/zed-giftshop-storefront/>

## What it does

Every stage of a gift purchase works end to end in the browser:

| Stage | Page |
| --- | --- |
| Discover | `index.html` — hero, offers, categories, featured, best sellers, occasion pills, new arrivals, newsletter |
| Browse | `shop.html` — facets (category, brand, price band, occasion, recipient, size, colour, availability), six sorts, pagination, URL-synced filters |
| Product | `product.html?id=…` — gallery, size/colour variants, quantity, stock, description, specifications, delivery policy, reviews |
| Cart | `cart.html` — quantity steppers, save for later, delivery choice, promo codes, live totals |
| Checkout | `checkout.html` — four steps (contact → delivery → payment → review) with per-step validation |
| Payment | simulated M-Pesa, card, bank transfer and cash on delivery, including failure and retry |
| Confirmation | `confirmation.html?order=…` — order number, receipt, what happens next |
| Tracking | `track.html` — order lookup with contact verification, courier details, delivery timeline |
| Review | `review.html?order=…` — per-product star rating, text, emoji photo, delivery rating |
| Account | `account.html` — sign in / register, orders, wishlist, addresses, notifications, profile, reorder |
| Admin | `admin.html` — revenue stats, order table, status controls, reviews moderation, stock editing, fulfilment simulator |
| Static | `about.html`, `contact.html` — story, delivery table, returns, privacy, terms, FAQs, corporate quote form |

## Architecture

No build step, no dependencies, no backend. Each page loads `store.js` plus one
page script.

| File | Purpose |
| --- | --- |
| `store.js` | The engine: 30-product catalogue, generated SVG product art, cart, wishlist, saved-for-later, coupons, delivery tiers, orders, order lifecycle, simulated payments, reviews, account, notifications, and the shared header/footer/quick-view shell exposed as `window.ZED` |
| `zed.css` | Design system: green palette, header and mega menus, product cards, facets, PDP, cart, four-step checkout, timeline, tables, tabs, responsive rules |
| `index.html` | The only hand-authored page shell; the rest are generated from a shared template |
| `home.js` … `contact.js` | One controller per page |
| `.nojekyll` | Serves the folder as plain files on GitHub Pages |

Page shells are generated by `build-pages.js` + `pages.js` (kept outside the
published folder) so the head, header mount, footer mount and quick-view modal
stay identical across all twelve pages.

## State

Everything lives in `localStorage` under `zed.store.v1`:

```json
{
  "cart": [], "saved": [], "wish": [], "orders": [], "reviews": [],
  "addresses": [], "user": null, "coupon": null, "notify": [], "seeded": true
}
```

A demo order `ZED-2026-482913` is seeded on first visit so tracking, reviews and
the admin dashboard have content immediately.

## Demo behaviours

- **Promo codes** — `ZED10` (10% off), `WELCOME15` (15% over KShs 3,000),
  `FREEDEL` (free delivery), `SAVE500` (KShs 500 off).
- **Card payments** — any 16-digit number succeeds except `…0002` (declined)
  and `…0069` (expired card). Nothing is charged.
- **M-Pesa** — any number works; numbers ending in 0 or 1 are declined about a
  quarter of the time so the retry path can be exercised.
- **Coupons cannot be applied to an empty cart**, and advancing a delivered
  order past fulfilment is refused.

## Local preview

```bash
python -m http.server 8899
# then open http://localhost:8899/index.html
```

Any static file server works. A server is required rather than opening the files
directly, because the pages read the URL query string for product ids and
filters.
